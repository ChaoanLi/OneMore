# 旧数据迁移

旧模型没有空间归属，程序不会推测谁属于哪一拨人。升级保留全局账号、登录和邮箱，旧好友/活动等业务表保留在同一个数据库内，但普通 API 不再读取；旧活动发件项不会发送，旧 ICS 链接失效。

首次升级已有数据库时，在同目录自动生成 `couju.db.pre-spaces-时间戳.bak`（SQLite `VACUUM INTO`，包含 WAL 中的已提交内容）。备份、数据库、运行日志均不能提交到 GitHub。

最简单的使用方式：账号创建新空间，通过空间链接申请并由管理员批准，从空白开始。

需要导入时：先在应用内建立目标空间并确认管理员身份；停止正在使用该数据库的服务，保留备份，使用该空间及**完整内部用户 ID**清单。该工具仅能在服务器本地运行，没有远程导入 API。

```bash
# 默认预览：打印待导入及跳过数量，不添加成员或导入内容
npm run import:legacy -w @couju/server -- \
  --db /absolute/path/couju.db \
  --space sp_TARGET \
  --members u_OWNER,u_FRIEND_A,u_FRIEND_B

# 检查预览后，使用同样参数并增加 --apply
```

名单必须包含目标空间管理员；所有账号必须存在。应用实际导入前再做一致性备份，导入和成员归属在一个事务内完成。

只有全部关联成员在清单内的对象才导入，包括活动发起者、邀请、报名、正式/候补名单和角色分配；想玩、圈子及转化关联也必须完整。缺少任意关联者会跳过整个对象，输出数量和原因。不会自动增加陌生人或删减参与者来凑成导入条件。

不导入旧通知、邮件任务和订阅令牌。相同清单重复应用会返回 `alreadyImported: true`；与已有目标对象 ID 或活动短码冲突时停止，禁止覆盖。需要重新安排名单时先查看输出并保留备份，不要直接删除原数据库。

恢复备份前先停止服务，再用备份替换完整数据库并移开旧 WAL/SHM 文件；不要在正在运行的数据库上直接覆盖文件。备份中含账号恢复凭证和私人数据，请按数据库本身保护。
